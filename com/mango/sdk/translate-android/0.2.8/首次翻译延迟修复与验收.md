# 首次翻译延迟修复与验收

> 冷却硬性底线：所有现役引擎失败至少5分钟；Google免费直连错误90分钟；所有非自建引擎429按被封处理，停用90分钟。自建引擎429才使用容量限流策略，也不能低于5分钟。首选、兜底及预热都检查冷却。

版本：`0.2.7`。`0.2.6` 不包含本文新增 API 和行为，宿主须升级到0.2.7才能获得修复。

## 问题与修复

2026-09-08 的宿主日志显示 SDK 调用到结果之间有 5.47 秒空白。源码确认 Google 免费接口先等待超时、仅预热选中引擎和固定短冷却会导致反复等待。最终是否由 48 接住、其握手与服务端耗时如何分配，原报告没有实际尝试事件，仍需设备复测。

- `TranslationHost.isGoogleReachable()`：每次免费 Google 请求与预热读取实时可达性。默认沿用 `isGoogleBuild()` 作为宿主否决条件。SDK 自带异步探测，不依赖宿主改代码：状态未知或探测中直接走备用链，成功后才放行 Google。探测成功缓存2分钟，网络切换后重新确认；失败停用90分钟并持久化。宿主返回 false 时同时跳过探测。
- `preconnect()` / `preconnect(id)`：从选中或指定引擎开始，沿原兜底顺序预热前两个符合资格的健康引擎；跳过未配置、非会员付费、不可达、冷却或闸门未就绪的引擎。不占用请求闸门、不取用凭据、不消耗翻译额度，预热失败不记录冷却。无参数且尚无选择时可从兜底链开始。
- 无历史选择时，默认使用首个健康、免费且允许选择的引擎。历史选择和用户主动选择保留原 ID，临时不可达只影响本次执行；隐藏引擎可参与兜底和预热，但不成为默认用户选择。
- **Google / Google Client 免费直连发生403、429、5xx或网络失败均冷却 90 分钟**，期间请求与预热跳过该引擎。其他引擎网络错误、408、5xx及自建服务429按5分钟 → 10分钟 → 30分钟 → 引擎配置上限递增，每一步受各自上限约束；鉴权和证书错误取本引擎上限。所有现役引擎失败冷却至少5分钟，Google直连90分钟。短 `Retry-After` 不能缩短该底线；旧版本残留的5秒等短冷却按同一底线提升，保留原始失败时间。次数跨冷却窗口保留；成功翻译只重置实际成功引擎，备用引擎成功不会重置失败的 Google 引擎。自建服务不套用 Google 直连的90分钟规则。
- `setDebugLogging(true)` 只开启新的元数据日志，原有可能包含内容的日志保持关闭。回调新增 `onEngineSkipped(id, reason)`、`onFallback(fromId, toId)`，与尝试耗时回调配合查看路径。

## 宿主接入

SDK 自带保护随升级生效。宿主若已有探测缓存，可在原 `TranslationHost` 实现里增加以下可选否决与观测接口：

```java
@Override public boolean isGoogleReachable() {
    // 读取 App 已有探测缓存；未知、探测失败时返回 false。
    // 不在这里执行 socket、DNS 或其他阻塞探测。
    return googleReachabilityCache.isReachable(); // 替换为宿主自己的缓存读取
}

@Override public void onProviderAttemptFinished(
        int engineId, String outcome, long durationMs, int httpStatus) {
    Log.d("TranslateTiming", "engine=" + engineId + " outcome=" + outcome
            + " durationMs=" + durationMs + " httpStatus=" + httpStatus);
}

@Override public void onEngineSkipped(int engineId, String reason) {
    Log.d("TranslateTiming", "engine_skipped engine=" + engineId + " reason=" + reason);
}

@Override public void onFallback(int fromEngineId, int toEngineId) {
    Log.d("TranslateTiming", "fallback_to from=" + fromEngineId + " to=" + toEngineId);
}
```

回调可能来自不同线程，需快速返回；不要输出凭据、URL、原文或译文。调试包也可直接启用 `TranslationSdk.setDebugLogging(true)`，日志标签为 `MangoTranslation`；关闭时传 false。

SDK 初始化并恢复选择后，在进入翻译页面时调用 `TranslationSdk.preconnect()`。它异步执行，返回 true 表示至少一个目标已安排、执行中或近期预热过，不保证下一请求复用连接，也不保证业务成功。无需继续硬编码 `preconnect(48)`。

Google 后台探测使用不带鉴权和正文的 HTTPS `HEAD /`，连接池与翻译共享，超时3秒；当前翻译不等待它，单引擎并发调用合并为一次探测。仅2xx及根路径HEAD常见的404/405视为可达；403、429、5xx和重定向视为不可用并停用90分钟。探测不保证翻译业务成功。探测失败的90分钟停用与普通预热失败不冷却是两种独立行为。事件为 `probe_response`、`probe_http_error`、`probe_timeout`、`probe_network_error` 等；宿主无需复制一份探测实现。

预热结果使用 `onProviderAttemptFinished`：`preconnect_response`、`preconnect_timeout`、`preconnect_network_error` 等。相同 Origin 和传输类型会合并，只产生实际发出 HEAD 的事件。`response` 表示 Provider 请求流返回，不代表业务翻译成功；业务结果需看翻译成功回调和 `actualEngineId`。无法取得 HTTP 状态时为 0。

## 验收

1. 国内无代理冷启动，缓存 Google 不可达。选中 8 时应出现 `engine_skipped engine=8 reason=unreachable`，随后是实际备用引擎；不得出现 8 的 HTTP 超时尝试。预热应指向已配置且健康的备用引擎。
2. 使用未缓存的新文本，每次间隔 10 秒，至少重复 3 次。不可达状态下均应跳过 8，记录 SDK 调用到成功回调的耗时及实际引擎 ID。
3. 不实现新宿主接口，模拟 Google 域名黑洞：当前翻译不得等待探测完成，后台 `probe_timeout` 后重启 App 仍应跳过 Google。再模拟已探测成功、真实翻译请求随后超时。首次失败立即冷却 90 分钟，间隔 10 秒、1 分钟重复请求均跳过该通道。冷却内请求应走备用链，预热不能把失败计数清零。
4. Google 可达性从 false 切换为 true 时，每次调用立即读取新值；仍需通过SDK异步探测；有冷却或请求闸门时继续遵守它们。真实 Google 翻译成功后，其连续失败计数重置。
5. 检查非会员不请求付费 Provider、历史选择保持不变、取消行为与单条/批量翻译正常。无健康免费候选时明确失败。

目标为 SDK 段接近 1 秒、最差不超过 2.5 秒，但这是设备与服务端联合验收目标，不能由本地单测或预热保证。本次未增加宿主 OkHttpClient/ConnectionPool 注入接口（报告 R5 为可选项）。

## 本地验证结果（2026-09-09）

`scripts/verify.ps1` 全部通过：SDK 122项、中台25项、自建服务61项测试，均无失败或跳过；Release AAR 已生成。回归测试使用受控探测结果和时钟验证未知状态立即跳过、单条/批量入口、探测合并、90分钟停用跨实例保留、恢复探测、网络切换及过期回调隔离。它们不等同于国内真机端到端耗时验收。

本次发布SDK 0.2.7，不部署服务或修改宿主App；仍使用0.2.6的宿主不会自动获得修复。

## 复查修正

- 正确性：修正第三方429封禁与自建限流混用、部分首选引擎绕过冷却、403/429/5xx探测误判成功、并发清零覆盖新冷却、时间回拨丢失冷却时长、旧版短冷却沿用等问题。
- 性能：本地HTTP模拟验证无响应探测异步返回；冷却中的首选不进入Provider请求。国内真机耗时仍待验收。
- 安全：探测保持无鉴权、无正文、不跟随重定向；本轮未修改线上配置或凭据。
- 可维护性：全现役引擎矩阵检查5分钟底线及第三方429的90分钟封禁；Google与自建引擎有分别断言，较晚错误不能缩短已有封禁。

## 整体流程复查

本轮从配置到回调检查完整链路，冷却底线和第三方429封禁策略没有降低。

| 环节 | 检查与修正 |
|---|---|
| 初始化与配置刷新 | 配置解析失败仍保留旧运行时；配置移除引擎后，旧Translator的新请求不再执行被移除的引擎；清空运行时明确返回SDK_NOT_INITIALIZED。 |
| 选择与权限 | 保留用户ID，按本次会员快照过滤备用引擎；显式选择与历史会员过期路径维持既定行为。 |
| 探测与冷却 | 未确认可达直接跳过；第三方429及Google直连长冷却保持90分钟，其他失败至少5分钟。 |
| 请求与错误 | 解析异常进入失败冷却；宿主回调异常在SDK边界隔离，不再误触发新的Provider调用。 |
| 统一兜底 | 旧有道、Google VIP、微软VIP的直接百度分支改走统一链，遵守已尝试集合、资格、冷却、语言与预算检查。 |
| 取消与回收 | 多级兜底以及会员/额度包装器都持有备用控制器；关闭向下传递，终态释放备用资源，迟到或重复回调被抑制。 |
| 本地链路测试 | 覆盖两级兜底取消、最终成功只回调一次、旧百度入口、宿主回调抛异常、关闭后的主请求回调、配置被移除和运行时被清空。 |

本地验证不代表线上已经恢复；SDK 0.2.7发布后仍需宿主升级并完成国内设备端到端耗时验收。
